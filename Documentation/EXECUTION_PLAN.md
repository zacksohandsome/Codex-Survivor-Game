# 開發執行計畫

建立日期：2026-11-03（Asia/Taipei）  
版本：1.2；狀態：M0 環境驗證完成；依使用者指示本次停在 M0，尚未開始遊戲實作。

## 1. 目標與依據

依據 [README](README.md)、[遊戲設計](GAME_DESIGN.md)、[系統規格](SYSTEM_SPEC.md)、[技術規格](TECHNICAL_SPEC.md)、[工作規範](CODEX_WORKFLOW.md) 與 [驗收規格](QA_AND_DELIVERY.md) 執行。本文拆分工作與驗收順序，不取代原始規格；進度與通過證據集中於 [里程碑追蹤](MILESTONES.md)。

先以佔位素材完成主選單 → 武器選擇 → 10 分鐘生存／死亡 → 結算 → 局外強化 → 重啟讀檔的 MVP。提供測試、錄影與 Windows Build，等待使用者確認後，再補齊正式內容與公開 Demo 品質。

最終固定範圍：Windows 64-bit、單一角色、固定封閉競技場、WASD、自動攻擊、5 種武器（同持最多 3 種，各 5 級）、5 種被動、2 種特殊技能、5 項局內屬性升級、3 種普通敵人、3 分鐘精英、7 分鐘 Boss、五段難度、5 種局外強化、JSON 存檔、繁中／英文、完整設定與統計。Boss 擊殺不是勝利前提。

不擴充多人、手把、護盾、暴擊、續玩、複雜組合系統、教學或獨立操作說明畫面。平衡與效能調整安排於完整循環之後；有界物件池與安全存檔則從相關系統建立時納入。

## 4. 預計檔案與資產

## 5. 驗證與證據策略

| 類型 | 主要案例 | 執行時機 |
|---|---|---|
| Edit Mode | 防禦遞減且最少 1 傷害、屬性加總／上限、經驗溢出、抽選優先與去重／欄位／滿級、購買退款、JSON 完整性與遷移 | 對應規則實作後及整合回歸 |
| Play Mode | 移動／碰撞、無敵時間、彈體只命中同敵一次、池重置、暫停所有計時、釋放後重新輸入、場景卸載、結算只一次 | M1 起逐步增加 |
| 故障測試 | 寫檔失敗不扣款、主檔與多份備份損毀、保留損毀檔、遷移失敗、非預期重載不重複入帳、中途退出不保存本場 | M4；M11 回歸 |
| 實際遊玩 | 從主選單完整玩到勝利及死亡，購買後重啟確認；暫停、升級、失焦與第二場狀態清空 | M5、M7、M11 |
| Windows | 啟動、完整循環、Player.log、存檔與設定跨重啟、視窗切換及顯示回復 | M5、M8、M11 |
| UI／語系 | 四解析度 × 視窗／全螢幕、雙語長文與缺字、繁中備援、15 秒逾時還原、世界視野一致 | M8、M11 |
| 平衡／效能 | 不同構築可通關、約 10～15 場升滿局外強化、滿載與長時間遊玩 | M10 |

快速測試可用可重現的時間／隨機種子控制，但僅限測試入口；MVP 與最終驗收都必須保留正常時間尺度的 10 分鐘實玩證據，不以快轉代替。勝敗同幀情況驗證實際事件順序及只結算一次。

效能報告記錄本機硬體、解析度、Build 版本、測試時長、敵人／彈體／掉落／VFX 數量、平均及最低 FPS、CPU 與記憶體。M10 記錄實際採用的負載、取樣方法與可接受標準；未達 1080p 穩定 60 FPS 必須列瓶頸及修正證據，不把未量測宣稱為通過。不得以合併／略過傷害數字、遺失掉落價值或修改核心內容達標。

證據放於 Documentation/Reports/Mxx/，至少含 report.md、測試結果、Console／Player.log 摘要及截圖。錄影、完整 Build 與大型原始報告可置於 Git 忽略的 Recordings/、Builds/，報告需註明確切相對路徑、版本及取得方式；交付時隨附，不只留本機路徑。

## 7. 進度、文件與變更管理

以里程碑通過條件排程，不先承諾未驗證的日期或工時。M0 完成後，依工具可用性與首次實作速度補估各階段工時；每階段實測後再更新預估。M5 使用者確認與必要授權等待時間單獨記錄，不算成實作完成。

每個里程碑開始時：確認依賴、列出工作與預計變更檔案、補完數值／規則決策、列測試案例。執行時按可獨立驗證的功能拆分，發現 Bug 依 QA 的阻斷性／嚴重／一般／輕微分類處理。完成時依序驗證、修正、更新文件、檢查差異並提交本次工作，最後附可驗證成果與 Commit ID。沒有實際測試或必要證據的項目保持未完成。
